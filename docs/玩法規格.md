# GlassTerris 玩法規格書 (v0.12.0)

本文件為 **GlassTerris**（粉紅磚牆俄羅斯方塊變體）之核心玩法規格文件。
所有規則、幾何演算、常數設定與物理行為均以原始程式碼（`js/`）及自動化單元測試（`test/logic.test.js`，共 32 項規格測試）為唯一事實來源（Single Source of Truth, SSOT）。

> **給接手維護與二次開發者的警示**：
> 本作看似為俄羅斯方塊變體，但核心循環本質為**動態升牆與局部消行下削的生存對抗**。
> 本規格書中記錄的每條規則與幾何限制，皆經歷過實機逆向量測與多次使用者驗證推翻（見第 8 章）。請勿以「標準俄羅斯方塊直覺」隨意回滾任何規則。

## 1. 遊戲核心循環與視覺標的

### 1.1 核心循環
1. **背景壓迫（升牆）**：全實心粉紅磚牆每隔週期自底部向上生長一列，整座牆體定時向上推升，壓迫玩家操作空間。
2. **關卡空格（尋路）**：開局先選擇「簡單：中央長直線空格」或「困難：8 列像素愛心空洞」。
3. **方塊填補（消行）**：玩家控制下落的標準 Tetromino 方塊深入細縫，補滿水平列缺口。
4. **碎裂波與削牆（反擊）**：滿列引發橫向碎裂波粉碎整排磚石，波掃畢後**上方整面牆整體塌陷閉合**，實質將牆體向下削矮一層，贏得生存空間。
5. **勝負判定**：在限時內盡可能透過大消行獲取高分，避免牆體頂破天花板。

### 1.2 視覺風格與關鍵要素
還原自 Instagram 廣告實錄影片（貼文 ID：`DdHF56DAWA5`）：
- **粉紅立體外框與 HUD**：亮粉色外框（`#f5378e`）帶厚陰影。頂部 HUD 呈現青色斜體倒數時間（`TIME xxx`）、中央大字分數（隨碎裂波前進即時跳動）、右上重玩鍵（`↻`）與右下靜音鍵（`🔇`）。
- **純色底板**：場地底板使用單一淺粉色 `#fbe3eb`。
- **玻璃磚**：粉紅主體、受光亮邊、暗色落陰與磚縫；牆體頂部不另加凸出頂蓋或厚度側面。
- **底層預覽列**：正準備升上來的下一列（`nextRow`）預先渲染在場地底層外緣，玩家可提前觀察縫隙走向。
- **橫向碎裂波與粒子爆裂**：消行時碎裂波由左向右推進，磚塊呈現破裂紋理隨即炸開，伴隨旋轉碎屑粒子拋灑。
- **重力落體動畫與塌陷接縫**：抽行塌陷與踩空殘磚下落皆具備自由落體加速度動畫；塌陷結合處標記暗紅色接縫線（`#a82d60`）。

## 3. 場地與幾何網格規格

### 3.1 網格系統與座標系
- **網格維度**：`COLS = 34` 欄，`ROWS = 60` 列。
- **幾何座標**：左上角為原點 $(0, 0)$，向右為 $+x$（$0 \le x < \text{COLS}$），向下為 $+y$（$0 \le y < \text{ROWS}$）。
- **格子旗標（Bitmask Flags）**：
  - `EMPTY = 0`：透空無磚，露出場地條紋背板。
  - `FILLED = 1`：實心磚塊，參與剛體碰撞。
  - `SEAM = 2`：崩塌接縫標記，於單元格頂緣繪製暗紅裂線。
- **碰撞邊界**：$x < 0$、$x \ge \text{COLS}$ 或 $y \ge \text{ROWS}$ 視為 `FILLED`；頂部出界 $y < 0$ 視為 `EMPTY`。

### 3.2 初始牆面生成（`Board.prototype.generateWall`）
開局時牆體並非全空，而是由底部依凹凸輪廓填起實心磚：
1. **基準深度**：自中央起點 $d = \text{WALL.startDepth}$ 展開。
2. **漫步拋物線**：
   - 逐欄有 $\text{WALL.stepChance}$ 機率變動 $\pm 1$ 格（$\text{WALL.bigStepChance}$ 機率為 $\pm 2$ 格）。
   - 疊加兩側拋物線抬升量：
     $$\text{lift} = \text{round}\left( \text{WALL.edgeLift} \times \left(\frac{|x - \text{mid}|}{\text{mid}}\right)^2 \right)$$
     其中 $\text{mid} = \frac{\text{COLS} - 1}{2} = 16.5$。限制深度介於 $[\text{WALL.minDepth}, \text{WALL.maxDepth}]$。
3. **三輪平滑夾制（3-Pass Clamp）**：
   - 雙向來回平滑掃描 3 輪，強制保證相鄰欄位落差 $|depth[x] - depth[x \pm 1]| \le \text{WALL.maxStep}$（預設 1 格），消除孤立斷崖。
4. **預留空格鋪設**：
   - 由頂列 $y = 0$ 往底列 $y = \text{ROWS}-1$ 逐列透過 `makeRow()` 生成，使後續升入底部的新列能延續所選關卡的空格序列。

### 3.3 預留空格系統（Pre-baked Gap System）
空格不再是開局在成形牆上挖出的洞，而是**隨每一列生成時預先留出**：
- **簡單關 `straight`**：每段直槽維持 12 列後才隨機左右移動一欄；轉彎列同時挖開新舊兩欄，形成較長但不會永遠固定在同一欄的連通空槽。
- **困難關 `heart`**：使用下列像素愛心模板。
- **像素愛心模板**：`HEART_GAP_ROWS` 由上往下定義 8 個橫切面，空格數依序為 4、8、9、7、5、3、1、1，拼成雙圓瓣、飽滿中段與尖角。
- **安全水平位移**：維持 `heartCenter` 與 `heartRow`；完成一顆愛心後有 `GAP.shiftChance` 機率左右移動至多 `GAP.maxShift` 欄，並以 `GAP.heartHalfWidth` 夾制，確保愛心不超出左右邊界。
- **預覽緩衝（`nextRow`）**：
  - `Board` 隨時常駐一列已預先生成好的 `nextRow`。
  - 渲染器將 `nextRow` 繪製於場地底部下方（$y = \text{ROWS}$），使玩家能清晰看見裂縫即將生長的位置。

## 4. 牆體推升機制（Wall Rise）

牆體定時自底部增生向上推動，是本作最關鍵的時間壓迫來源。

### 4.1 推升週期與難度平衡

**推升週期隨分數縮短**，不是固定值。分數越高、牆升得越快：

$$\text{riseMs} = \text{RISE\_MS} + (\text{RISE\_MIN\_MS} - \text{RISE\_MS}) \times \min\left(1,\; \frac{\text{score}}{\text{RISE\_SCORE\_FULL}}\right)$$

| 分數 | 推升週期 |
| :--- | :--- |
| 0 | 5000 ms/列（開局） |
| 1000 | 3720 ms/列 |
| 2000 | 2440 ms/列 |
| 2500 以上 | 1800 ms/列（封頂，不再更快） |

**為什麼綁分數而不是綁時間**：分數才代表玩家真的在推進。卡住不消行的人不會被額外懲罰，
消得越兇的人壓力升得越快，一場自然會收尾。

**`RISE_SCORE_FULL = 2500` 是量出來的**（貪心 bot 每秒一塊、各跑 8 局）：

| 設定 | 平均撐多久 | 平均分數 |
| :--- | :--- | :--- |
| 無加速（對照） | 214 秒 | 2423 |
| 5000 | 195 秒 | 2597 |
| **2500（採用）** | **152 秒** | **2098** |
| 1500 | 125 秒 | 1592 |

門檻 5000 太溫和（bot 打到結束只走到曲線一半，加速沒感覺，只縮短 9%）；
1500 太兇。2500 讓終盤分數逼近門檻，玩家真的會摸到最快速度，且比無加速縮短 29%。

- **底層推進**：
  1. 將暫存之 `nextRow` 填入網格底層 $y = \text{ROWS} - 1$。
  2. 網格既有資料整體向上平移 1 列（$y \to y - 1$）。
  3. 若第 0 列包含 `FILLED` 磚塊被擠出場外，判定為溢出（`spilled = true`），觸發 Game Over。
  4. 立即呼叫 `makeRow()` 重新備妥新的 `nextRow`。

### 4.2 非線性脈衝視覺位移（`riseOffset`）
- **視覺問題覆盤**：若將 1 格（12px）均攤在 5 秒內推升，每秒僅移動 2.4px，肉眼難以察覺推升感。
- **脈衝推升方案**：
  - 上升位移集中於換列前 $\text{RISE\_PUSH_MS} = 600$ 毫秒內完成，其餘 $4400$ 毫秒畫面保持靜止。
  - 使用 Smoothstep 曲線平滑插值：
    $$\text{frac} = \frac{\text{RISE\_PUSH\_MS}}{\text{RISE\_MS}} = 0.12$$
    $$t = \frac{\text{riseProgress} - (1 - \text{frac})}{\text{frac}}$$
    $$\text{riseOffset} = \begin{cases} 0 & (t \le 0) \\ 3p^2 - 2p^3 & (0 < t < 1,\; p = \text{clamp}(t, 0, 1)) \\ 1 & (t \ge 1) \end{cases}$$
  - 平均上升速度與難度完全不變，但推升瞬間具備明確力量反饋。

### 4.3 進行中實體座標同步
每當 `updateRise` 觸發推升完成時：
1. **碎裂波座標**：正在推進的碎裂波行號向上同步平移 1 格（$y \to y - 1$）。
2. **下落動畫座標**：正在執行的落下磚塊目標行號同步向上平移 1 格。
3. **下落方塊防擠壓**：空中下落中的玩家方塊（`pieceY`）向上抬升 1 格。若上方遭遇障礙，持續微調上移；若被完全夾死出界則觸發 Game Over。

## 5. 方塊生成與操作控制

### 5.1 方塊定義與發牌
- **方塊種類**：標準 7 種 Tetromino（`I`, `O`, `T`, `S`, `Z`, `J`, `L`，定義於 `js/pieces.js`）。
- **隨機機制**：標準 **7-bag** 產生器（`createBag()`），保證每 7 塊必出齊 7 種造型，杜絕特定方塊飢餓。
- **旋轉規則**：順時針轉置（4 個旋轉相位）。
- **踢牆偏移（Wall Kicks）**：旋轉遇阻時依序嘗試水平偏移 $\text{KICKS} = [0, -1, 1, -2, 2]$。

### 5.2 落下節奏曲線
- **基礎自然下落**：$\text{GRAVITY\_MS} = 240$ 毫秒/格。
- **加速極限**：$\text{GRAVITY\_MIN\_MS} = 120$ 毫秒/格。
- **加速曲線**（依累計遊玩時間爬升，爬到 1 之後就停在極限值）：
  $$t = \min\left(1,\; \frac{\text{elapsed}}{\text{RAMP\_SECONDS}}\right)$$
  $$\text{gravityMs} = \max\left(\text{GRAVITY\_MIN\_MS},\; \text{GRAVITY\_MS} \times (1 - t \times (1 - \text{GRAVITY\_RAMP}))\right)$$
  其中 $\text{GRAVITY\_RAMP} = 0.75$。
- **軟降間隔**：$\text{SOFT\_DROP\_MS} = 45$ 毫秒/格。
- **鎖定緩衝**：$\text{LOCK\_DELAY\_MS} = 320$ 毫秒。觸底微調移動或旋轉時重置計時器。
- **生成冷卻**：$\text{SPAWN\_DELAY\_MS} = 90$ 毫秒。

### 5.3 操作方式映射
- **觸控／指標事件（Pointer Events）**：
  - **點擊旋轉**：位移 $< \text{cell} \times 0.6$ 且歷時 $< 280\text{ms}$，觸發順時針旋轉。
  - **水平滑動**：以手指起點為基準，水平位移映射至對應欄位進行平移。
  - **向下拖曳軟降**：垂直下移顯著（$dy > \text{cell} \times 1.5$ 且 $|dy| > |dx|$）時啟用軟降。
  - **向下快甩硬降**：放開瞬間下衝距離 $> \text{cell} \times 3.5$、歷時 $< 320\text{ms}$ 且偏縱向，觸發硬降。
- **桌面鍵盤映射**：
  - `ArrowLeft` / `ArrowRight`：左右移動 1 格。
  - `ArrowUp` / `KeyX`：順時針旋轉。
  - `ArrowDown`：按住軟降，放開恢復。
  - `Space`：硬降至投影點（`ghostY`）並立即鎖定。

## 6. 落定、碎裂波與兩階段下墜物理

### 6.1 落定與原位固化原則（Lock & No Settle）
方塊觸底鎖定時，呼叫 `lockPiece()`：
- **快照比對**：取得落定前滿列狀態 `wasFull = board.fullRowMask()`。
- **寫入網格**：將方塊佔用之格子寫入 `FILLED`。
- **差分消行檢查**：
  $$\text{rows} = \{ y \mid \neg\text{wasFull}[y] \land \text{board.isRowFull}(y) \}$$
- **原位固化（禁忌防線）**：
  - **若未造成任何滿列（`rows.length === 0`）**：方塊**永久固定在當前落點，底下懸空的細縫空洞完整保留**。架在縫口上的方塊絕不向下沉降。

### 6.2 橫向碎裂波（Shatter Wave）
當 `rows.length > 0` 時，觸發消行流程：
1. 啟動橫向推進波 `startWave(rows, placed)`，波自 $x = 0$ 往 $x = \text{COLS}$ 前進。
2. 速度：$\text{WAVE\_COLS\_PER\_SEC} = 48$ 欄/秒。
3. 碎裂破壞：波覆蓋之實心單元格由 `FILLED` 變更為 `EMPTY`，拋灑粉紅破碎粒子 `burstCells`。
4. **即時逐磚計分**：每摧毀 1 塊實心磚，立即累加 $\text{SCORE\_PER\_BRICK} = 2$ 分，HUD 分數隨波即時跳動。
5. **完全消掉定義**：波掃至最右端出界後，該次消行才算正式完成，進入下墜階段。

### 6.3 兩階段下墜物理（`finishWave`）
碎裂波掃畢後，依序執行兩個互不干擾的物理階段：

#### 階段一：整面上牆下落塌陷（`Board.prototype.collapseRows`）
- 將被消掉的滿列整列抽離網格。
- **被抽離行上方之整座磚牆整體下落對應列數**，頂部稜線同步被削矮，直接閉合空帶。
- 頂部補充全空列。
- 塌陷斷層接合處標記 `SEAM` 旗標，呈現暗紅色接合裂線。
- 產生上牆磚塊之平移位移清單。

#### 階段二：當前方塊活體殘磚單欄下墜（`Board.prototype.dropFloaters`）
- 比對剛落定方塊之格子清單：過濾出**未被消除列摧毀的其餘殘餘格子**。
- 將殘餘格子依照 $y$ 座標**由下至上排序**，逐格沿所屬單一欄位向下探測，直到觸底或遭遇障礙為止。
- **關鍵幾何防線**：
  - `dropFloaters` **僅針對當前方塊之殘存格子運算，嚴禁對全盤掃描**。
  - 因為牆體內部原本就留有預先生成的 `EMPTY` 空格，若全盤下沉將會把內建細縫填平堵死。
- **連鎖削除**：只重新檢查「實際有殘磚落入」的列；若因此補滿整列，必須等待下落動畫完整結束後才啟動下一道碎裂波。不得直接掃描所有滿列，以免誤消牆體原生實心列。

### 6.4 自由落體物理動畫（`startFall` / `fallOffsets`）
磚塊下落為平滑動畫而非瞬間瞬移：
- **邏輯即時結算**：`collapseRows` 與 `dropFloaters` 呼叫當下，網格數據已立即更新至最終落點，確保後續碰撞、判定無跨幀競態。
- **畫面平方反比插值**：
  - 單格基準時長：$\text{FALL\_MS} = 200$ 毫秒。
  - 依物理重力演算時長：$t_{\text{dur}} = \text{FALL\_MS} \times \sqrt{\max(1, \text{dist})}$。掉落距離越遠總時長越長，符合真實驗算。
  - 自由落體加速位移公式：
    $$\text{offset} = \text{dist} \times (1 - p^2) \quad \left(p = \frac{t}{t_{\text{dur}}}\right)$$
  - 起步平緩、加速重擊，每塊磚依自身距離獨立計算動畫，維持同等重力加速度感。

## 7. 勝負判定與計分模型

### 7.1 純化計分模型
數值定義於 `js/config.js`：
1. **方塊落定分**：`SCORE_LOCK = 0` 分（實機錄影方塊落地不跳分）。
2. **硬降深度分**：`SCORE_HARD_DROP_PER_CELL = 0` 分。
3. **碎裂波逐磚摧毀分**：`SCORE_PER_BRICK = 2` 分/磚。
   - 消滿 1 整列（34 格）約得 68 分。
   - 插入深縫引爆 10 列大消除時，連續粉碎跳加約 680 分。
   - 遊戲全部得分 **100% 來自碎裂波摧毀磚石**。

### 7.2 遊戲結束條件（Game Over）
**唯一的結束條件是頂部封頂（Top Out）**，結算標題固定「堆到頂了」。

時間不是結束條件：`game.elapsed` 只會往上累加，HUD 以 `M:SS` 顯示累計遊玩時間，
玩多久都不會因此結束。成績由「撐多久」與「拿多少分」共同構成。

頂部封頂的三種觸發方式：
- 場上實心最高點達到警戒線：$\text{board.surfaceDepth()} \le \text{TOP\_OUT\_DEPTH} = 2$。
- 新方塊出生點即遭遇阻擋重疊（`!board.fits`）。
- 牆體向上推升時，頂部第 0 列包含實心磚被推出界外（溢出）。

## 8. 歷史教訓：被推翻的七大規則（禁忌手冊）

本專案經歷七次重大設計推翻，理由皆源自使用者實機體驗與實況錄影對照。**接手者嚴禁將其改回舊方案**：

### 8.1 曾推翻 1：實心死牆無細縫
- **曾經做法**：開局牆體為完全實心，稜線下毫無孔隙。
- **為什麼錯**：使用者實測反饋：「原本應該要有幾個空格可以讓積木放入」。長條落下毫無作用，無法形成消除。
- **現在做法**：牆體內部預先生成可供方塊深入的像素愛心空洞。

### 8.2 曾推翻 2：全盤物理沉降（Settle）
- **曾經做法**：消行後整面牆每欄執行全盤重力下沉，懸空磚石自動往下壓實。
- **為什麼錯**：使用者明確反饋：「不是所有會往下填壓」。更嚴重的幾何問題是：整盤沉降會直接把牆體內部預留的空格填滿壓平，整條細縫直接消失，造成死局。
- **現在做法**：僅有消行後該方塊未消掉的殘磚（`dropFloaters`）會下落；既有牆體結構不動。

### 8.3 曾推翻 3：在既有牆面上動態開鑿細縫（openSlot）
- **曾經做法**：牆生成後透過演算法向深處挖洞（`openSlot`），被填滿後計時重新挖開（`updateSlots`）。
- **為什麼錯**：動態開鑿破壞了牆體的有機生成，且開鑿動畫與補裂時機容易與推升互相打架，產生孤立懸空磚。
- **現在做法**：廢除 `SLOT` 設定，改為**從底層升上來的每一列預先留好空格（`GAP`）**，每 8 列組成一顆像素愛心。

### 8.4 曾推翻 4：同時開放 3 條細縫
- **曾經做法**：場上同時維持 3 條縱向細縫（`SLOT.target = 3`）。
- **為什麼錯（數學幾何死局）**：多條細縫深度重疊，上半部每一列都同時短缺 2~3 格。除非玩家在同一水平面同時塞滿 3 條縫，否則無法消行。Bot 實測 5 局 0 消除。
- **愛心例外**：愛心的多格空洞屬於同一個局部輪廓，而非貫穿全牆的多條獨立縫；仍需以整局實測持續觀察填補難度。
- **現在做法**：一列僅保留單一主裂縫（轉彎處重疊 2 格），確保每列只差 1 格即可消除。

### 8.5 曾推翻 5：消除後原地留懸空橫帶、牆不往下崩
- **曾經做法**：依單張截圖誤判，滿列消掉後原地清空留成透明橫帶，上方的牆完全不往下落。
- **為什麼錯**：留橫帶導致牆面永遠無法被削矮，玩家堆在稜線上的死重不可逆，Bot 實測 8 局全部在 20 多塊內封頂暴斃，玩法完全不成立。
- **現在做法**：波掃完後**整面上牆整體下落閉合（`collapseRows`）**，牆面實質被「往下削掉」一層。

### 8.6 曾推翻 6：落定時無條件讓踩空格子下落
- **曾經做法**：任何方塊一落定，只要底下懸空就立刻沿縫滑落。
- **為什麼錯**：破壞了俄羅斯方塊「架橋」與橫跨縫隙的基本操作手感，玩家無法將橫條搭在縫口兩側。
- **現在做法**：**沒消到列時完全不動**，架在縫口上的方塊留在原地；只有在觸發消行後，剩下的殘磚才會沿豎井掉落。

### 8.7 曾推翻 7：落定給分與硬降加分
- **曾經做法**：落定加 10 分（`SCORE_LOCK = 10`），硬降每格加 1 分（`SCORE_HARD_DROP_PER_CELL = 1`）。
- **為什麼錯**：逐格比對參考實錄影片時發現，方塊觸底與硬降瞬間分數維持 1300 完全不動（秒數 40.0~41.6），僅在碎裂波掃過時跳動。
- **現在做法**：兩者全數歸零，分數完全由碎裂波逐磚累加（`SCORE_PER_BRICK = 2`）。

## 9. 逆向工程與數值量測方法論

本專案之尺寸、時間與速度並非憑空假設，其量測方法具備高度工程複用價值：

### 9.1 Playwright 逐格 Seek 與接觸印樣分析
在欠缺獨立 ffmpeg 的環境下，利用 Playwright 控制瀏覽器播放錄影影片，透過 `HTMLVideoElement.currentTime` 實施高精度逐格 Seek，截取關鍵影格拼接成接觸印樣（Contact Sheet），精確捕捉到方塊落定到碎裂波發動、分數跳動的毫秒級生命週期。

### 9.2 像素自相關測量單元格邊長
- 對牆體純磚區域之水平與垂直灰度階躍進行自相關（Autocorrelation）分析與峰值距離計算。
- 證實單元格像素邊長嚴格為 **12px**。
- 根據有效遊戲區域（408×719px）精確回推網格尺寸為 **34 欄 × 60 列**。

### 9.3 邊緣輪廓差分與升牆發現
- 逐欄擷取不同時間點之牆體頂部邊界輪廓（Rim Profile）。
- 比對兩次未發生消行的時間截點，發現全場柱高整體以 5 秒/列 的速率單調上升，從而還原出原版隱蔽的「底部定時升牆」機制。

### 9.4 嚴格對照組檢驗機制
- 在推導任何量測結論前，必須先行比對「同一格與自己比對」以及「無消行發生的前後影格比對」。
- 透過對照組校準，及時排除了視窗微幅滾動、晃動以及誤把過渡動畫當常態的系統誤差。

### 9.5 貪心決策 Bot（Greedy Sim Bot）
撰寫自動化決策 Bot，以每秒出 1 塊的節奏模擬整局操作，量化分析不同參數組合下的平均生存磚數、消行數與 Top Out 率，作為平衡調整的硬性基準。
